The pull requests that reach you, at one desk.

gh-desk is a gh extension. The pull requests waiting for your review, your own, and your notifications sit in one terminal screen. Read the diff, approve and merge a dozen at once, and ask Claude about the one you are unsure of.

Below is gh-desk itself, compiled to WebAssembly and running in your browser against a made-up GitHub. Nothing you do here leaves the page.

~ — gh desk
Loading gh-desk…
or click the terminal and type

Things to try

Look before you merge

p opens the pane under the list: the description beside the checks and reviews. v switches it to the diff, ] and [ move between files, and J K scroll it.

Merge the bots in one go

Move to the bots and press b to unfold them, S to pick the rule dependency bots, then M. The popup says how each will be merged, and Claude reads the release notes for the ones that need care.

Ask Claude about one

i on a pull request asks Claude to review it, in a worktree of its head. ctrl+r then drafts the review to post. Here the answers are written in advance.

Or tell Claude what you want

C and type merge the bots with passing checks. Claude plans what to show and select; enter applies it, and nothing is sent until you confirm.

Your notifications

4 or tab goes to the inbox: the pull requests in your notifications, with why each is there. d marks one done.

Every key

? lists the keys of the screen you are on. They are bound by action name, and each can be changed in the config file.

Make it yours

Everything lives in one file, ~/.config/gh-desk/config.toml. The first run writes it with every setting described and commented out, so you change a line, not a blank page. A mistake is reported at its line, with what was likely meant.

Tabs are searches

Each tab is a GitHub search, split into groups by whom a review is asked of: you, a team of yours, or neither, with the bots apart. Add a tab for the repository you own, fold the groups you look at last.

[[tabs]]
name   = "review"
query  = "is:open is:pr review-requested:@me archived:false"
groups = ["you", "team", "bots"]
folded = ["bots"]

[[tabs]]
name  = "infra"
query = "is:open is:pr repo:acme/infra archived:false"

[[tabs]]
kind = "inbox"
name = "inbox"

Rules pick what is safe to merge

S offers your rules. A rule can name the bots, the packages a bump may touch (read from its description), the size, the age, and whether the checks pass. Pick one, look at what it caught, merge.

[[select]]
name      = "safe bumps"
authors   = ["renovate"]
packages  = ["golang.org/x/net", "actions/checkout"]
checks    = "passing"
max_lines = 50

[merge]
# the first the repository allows is used
methods       = ["squash", "merge"]
update_branch = "humans"

Claude, on your terms

Claude Code answers in your language and follows instructions of your own in every review. It runs with read-only tools in a worktree of the pull request; MCP servers and the skills of your plugins can be given to it too, as below.

[claude]
model        = "opus"
language     = "Japanese"
instructions = "Point out changes that have no tests."

Claude remembers how you got here

Give the conversation claude-recall as an MCP server, and Claude searches your past Claude Code sessions while it reviews: why the code was written this way, what was tried and dropped. --repo holds the search to the pull request's repository, so a review never reads the sessions of another. The tools under tools run without a prompt; keep WebFetch off with a server that reads your own data.

[claude.mcp_servers.recall]
command = "recall"
# GH_DESK_URL is the pull request's repository
args    = ["mcp", "--repo", "${GH_DESK_URL}"]
tools   = ["recall_search", "recall_list", "recall_export"]

Your keys, your colors

Every key is bound to an action by name, and the hints and the ? list follow what you bind. Nine themes, one for a dark terminal and one for a light one, picked by the terminal's background.

[keys]
merge   = "m"
approve = ["A", "ctrl+a"]

[theme]
dark  = "tokyonight"
light = "github-light"

gh desk config check finds the mistakes without starting, gh desk config show --diff prints what you changed from the defaults, and gh desk config edit opens the file and checks it when you close it.

It asks before it writes

An approval or a merge cannot be taken back on GitHub, so gh-desk is careful where it counts.

A popup lists every pull request

Approve, merge and review go through a confirm popup that says what will happen to each one, and marks the ones that change workflows or whose release notes call for care.

Only the head you saw

Each write is for the commit shown when you confirmed. A push in between stops it, rather than merging code you have not looked at.

Claude only reads

Claude reads a worktree of the head, with no tool that runs a command or changes a file. What it proposes, you apply; what it drafts, you send.

Waiting survives quitting

A merge waiting for checks or for auto-merge is recorded, and goes on at the next launch. No process is left running behind your back.

Install

  1. 1

    Install the extension

    gh-desk runs on the GitHub CLI and its login; there is no token to set up.

    gh extension install babarot/gh-desk
  2. 2

    Run it

    The first run writes the config file, then opens the pull requests waiting for you.

    gh desk
  3. 3

    Optionally, Claude

    With Claude Code installed and signed in, i and C work. Without it, everything else does.
