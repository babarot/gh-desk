The pull requests that reach you, at one desk.

gh-desk is a gh extension. The pull requests waiting for your review, your own, and your notifications sit in one terminal screen. Read the diff, approve and merge a dozen at once, and ask Claude about the one you are unsure of.

Below is gh-desk itself, compiled to WebAssembly and running in your browser against a made-up GitHub. Click it and type; nothing you do here leaves the page.

Make it yours

There is no file to write. One command opens a page in your browser, with gh-desk drawn above the settings and following each change before you save it.

gh desk config edit --ui

Try a theme, or change the columns or a key: this is that page, with made-up pull requests, and it saves nothing. Run the command, and the list is your own.

Tabs are searches

Each tab is a GitHub search, split into groups by whom a review is asked of: you, a team of yours, or neither, with the bots apart. Add a tab for the repository you own, fold the groups you look at last.

Claude remembers how you got here

Give the conversation claude-recall as an MCP server, and Claude searches your past Claude Code sessions while it reviews: why the code was written this way, what was tried and dropped. --repo holds the search to the pull request's repository, so a review never reads the sessions of another. The tools under tools run without a prompt; keep WebFetch off with a server that reads your own data. This one goes in the file: the page shows MCP servers and removes them.

[claude.mcp]
builtin = true

[claude.mcp.servers.recall]
command = "recall"
# GH_DESK_URL is the pull request's repository
args    = ["mcp", "--repo", "${GH_DESK_URL}"]
tools   = ["recall_search", "recall_list", "recall_export"]

Rather keep a file, in your dotfiles say? Everything on the page can be written by hand in ~/.config/gh-desk/config.toml; write only what you change. The configuration guide shows how, and the reference has every setting.

It asks before it writes

An approval or a merge cannot be taken back on GitHub, so gh-desk is careful where it counts.

A popup lists every pull request

Approve, merge and review go through a confirm popup that says what will happen to each one, and marks the ones that change workflows or whose release notes call for care.

Only the head you saw

Each write is for the commit shown when you confirmed. A push in between stops it, rather than merging code you have not looked at.

Claude only reads

Claude reads a worktree of the head, with no tool that runs a command or changes a file. What it proposes, you apply; what it drafts, you send.

Waiting survives quitting

A merge waiting for checks or for auto-merge is recorded, and goes on at the next launch. No process is left running behind your back.

Install

  1. 1

    Install the extension

    gh-desk runs on the GitHub CLI and its login; there is no token to set up.

    gh extension install babarot/gh-desk
  2. 2

    Run it

    The first run writes the config file, then opens the pull requests waiting for you.

    gh desk
  3. 3

    Optionally, Claude

    With Claude Code installed and signed in, i and C work. Without it, everything else does.

Getting started walks through the first run, and the docs explain the rest.
